# 虚拟股市 · astrbot_plugin_sharemarket

在 QQ 群里开一个**尽可能逼近真实 A 股规则**的多人联机模拟盘：开户、挂单撮合、涨跌停、T+1、佣金印花税、破产与重生、收益率排行榜。纯虚拟，不涉及任何真实资金。

- 目标平台：QQ 官方机器人（`qq_official`），也兼容 OneBot v11（`aiocqhttp`）
- 全部指令以 `/炒股` 开头
- 行情由一个**做市商引擎**驱动：虚拟做市商挂五档提供流动性，玩家的买卖压力反过来推动股价

---

## 功能特性

### 交易规则（对齐真实 A 股）

| 规则 | 实现 |
|---|---|
| 涨跌幅 | 主板 ±10%、创业板/科创板 ±20%、北交所 ±30%、ST ±5%；涨跌停价按昨收四舍五入到 0.01 |
| 封板 | 涨停不可买、跌停不可卖（按最新价封死判断） |
| T+1 | 当日买入次日才可卖，日终统一解锁 |
| 交易单位 | 买入须 100 股整数倍；零股仅可一次性清仓 |
| 委托 | 限价单，当日有效，日终自动过期 |
| 费用 | 佣金万 2.5（最低 5 元，双向）、印花税 0.05%（仅卖出）、过户费 0.001%（双向） |
| 资金账本 | 可用 / 冻结（挂单占用）/ 可取 三本账分离；卖出所得当日可用、次日可取 |
| 股份冻结 | 卖单未成交部分冻结，不可重复卖出同一批股份 |

### 撮合与行情

- **价格优先、时间优先**：玩家委托先与玩家对手单撮合，剩余与做市商成交
- **供需反噬**：净买入压力推高价格，净卖出压低价格（单 tick 冲击封顶 ±2%）
- **五档盘口**：`/炒股 盘口` 叠加玩家委托与做市商报价
- **三层因子价格模型**：大盘因子 → 板块因子 → 个股特质波动，另加均值回归与供需冲击，并做涨跌停钳制；所有波动率按"日"标定，改 tick 间隔不会改变一天的波动幅度
- **板块联动**：10 个板块各有一条独立的 AR(1) 因子，同板块个股同涨同跌；`/炒股 行情` 给出强势/弱势板块榜，`/炒股 个股` 给出所属板块及其涨跌

实测标定结果（`.dsh-code/vol_probe.py`，30 个虚拟日，6 个随机种子）：主板日波动 2.9–3.2%、创业板 3.7%、科创板 4.2%、北交所 3.7%（真实 A 股主板约 1.7%，这里刻意更凶）；等权大盘 1.4%；板块内平均相关 0.76 vs 跨板块 0.18。

### 凶险且大体随机

按"要和现实一样凶险、大部分完全随机"的取向实现：

- **肥尾**：个股冲击用 t 分布（自由度 3），极端行情比正态常见（实测收益峰度 4.8，正态为 3）
- **黑天鹅与狂欢**：大盘有罕见的暴跌/暴涨跳空，冲击带衰减；个股会**暴雷**（偏负）或暴涨
- **没有隐性保护**：均值回归强度压到 0.00005，价格接近纯随机游走，不存在"跌多了就会回来"
- **虚拟主力**：在暗处吸筹 / 拉升 / 派发 / 砸盘，制造放量长阳与阴跌；状态**不外露**，只给"主力净流入"
- **情绪指数** 0–100（🔥过热 / 😐中性 / 🧊冰点），过热与冰点会反向作用于大盘，但强度刻意很小
- 实测凶险度：最差单日 主板 −10.5%（跌停）/ 创业板 −16.6% / 科创板 −15.9%；30 日内个股最大回撤平均 −13%、最深 −25%；单日 |涨跌|>5% 占 12%
- 实测随机性：市场因子零均值（逐项收益分解验证），6 个种子的 30 日累计落在 **−11% ~ +10%** 之间——满仓死拿并不划算

### 破产与重生

- 分级判定：**L1** 资金不足一手（仅提示）→ **L2** 资金枯竭但持仓在（仅提示）→ **L3** 资金与持仓全空（判定破产）
- L3 后自助 `/炒股 重生`：冷却 **24 小时** + 资金按初始资金的 **50%** 发放 + 终身 **3 次**上限（堵死刷初始资金的漏洞）
- 破产玩家在排行榜以"墓碑"展示，移出收益率排名

### 其他

- 每 QQ 号唯一开户，防小号刷初始资金
- 交易指令限流：每 5 秒 1 单，防刷屏
- 持仓默认仅自己可见，排行榜公开
- 全服共享一个市场，所有群看同一盘面
- 数据持久化到 SQLite，重启不丢资产与持仓

### 股票代码：6 位原码 + 3 位短码

150 只股票分属 10 个板块，每只同时拥有 **6 位原码**（`code`，如 `600001`）与 **3 位短码**（`short_code`，板块拼音首字母 + 2 位序号，如 `JR01`）。`Stock.lookup` 同时接受两种码，原 6 位码完全保留向后兼容。

| 板块 | 短码前缀 | 板块 | 短码前缀 |
|---|---|---|---|
| 金融 | `JR` | 周期 | `ZQ` |
| 消费 | `XF` | 基建地产 | `JC` |
| 医药 | `YY` | 运输公用 | `YS` |
| 科技 | `KJ` | 汽车军工 | `QC` |
| 新能源 | `XNY` | 农业传媒 | `NY` |

短码由 `market/stocks.py::_build_pool` 按板块内顺序自动生成（`prefix + f"{idx:02d}"`），保证唯一。所有带 `<代码>` 参数的指令（个股/盘口/买入/卖出/k线等）都支持短码，例如 `/炒股 个股 JR01`、`/炒股 买入 XF03 1000`。

### 图片渲染与文本降级

行情、个股、盘口、持仓、资金、排行、龙虎榜、资金流、异动榜、道具、K 线等指令**优先发送图片卡片**（由 `render/cards.py` 与 `render/chart.py` 用 Pillow 绘制，深色金融终端主题）。当环境无 Pillow、事件对象不支持 `image_result`、或图片发送失败时，**自动降级为纯文本**——聊天里永远有输出。

- `render/cards.py` 提供 10 个 `render_*` 函数，缺 Pillow 返回 `None`；
- `main.py::_send_card()` 统一处理渲染 → 落盘 `data_dir/cards/` → `event.image_result` 发送 → 异常回退文本。

## 指令一览

下表是核心玩法；完整清单（玩法、融资融券、打新、道具、赛季等约 45 条）在群里发 `/炒股 帮助` 查看，命令手册已按「入门 / 看盘 / 交易 / 资产 / 玩法 / 进阶 / 设置」分组。

| 指令 | 说明 |
|---|---|
| `/炒股 开户` | 注册账户，领取初始资金（默认 100 万） |
| `/炒股 行情` | 大盘概览 + 情绪指数 + 涨停/跌停家数 + 板块榜 + 涨跌幅榜 |
| `/炒股 个股 <代码>` | 个股详情：现价、涨跌、开高低、涨跌停价、成交量、主力净流入 |
| `/炒股 盘口 <代码>` | 五档买卖盘 |
| `/炒股 搜 <关键词>` | 按名称 / 行业 / 代码搜股票 |
| `/炒股 k线 <代码> [分时\|日]` | K 线**图片**（Pillow 绘制：蜡烛/均线/成交量；分时为价格与均价曲线）+ MA/RSI/MACD 数字 |
| `/炒股 买入 <代码> <数量> [价格]` | 限价买入；省略价格按涨停价抢筹 |
| `/炒股 卖出 <代码> <数量> [价格]` | 限价卖出；省略价格按跌停价甩卖 |
| `/炒股 撤单 <单号>` | 撤销未成交委托（释放冻结） |
| `/炒股 持仓` | 我的持仓与浮动盈亏（仅自己可见） |
| `/炒股 委托` | 我的未成交委托（含冻结金额） |
| `/炒股 成交` | 我最近的 10 笔成交记录 |
| `/炒股 资金` | 可用 / 冻结 / 可取 / 总资产 / 累计盈亏 |
| `/炒股 排行` | 股神排行榜（按收益率，显示各自重生次数） |
| `/炒股 重生` | 破产后东山再起 |
| `/炒股 帮助` | 指令总览（按入门/看盘/交易/资产/玩法/进阶分组） |

指令组别名：`/stock`、`/cg`。

**示例**

```
/炒股 开户
/炒股 行情
/炒股 个股 600001
/炒股 个股 JR01              ← 也支持 3 位短码
/炒股 买入 600001 1000 4.50
/炒股 买入 600001 1000          ← 不填价格 = 按涨停价吃单
/炒股 持仓
/炒股 卖出 XF03 500 4.80
/炒股 撤单 12
```

## 安装

1. 把本插件目录放到 AstrBot 的 `data/plugins/` 下（目录名 `astrbot_plugin_sharemarket`），或在 WebUI 插件页从仓库安装。
2. 安装依赖（插件目录下的 `requirements.txt`）：

   ```bash
   pip install -r requirements.txt
   ```

   依赖只有 `aiosqlite>=0.19.0`。
3. 在 WebUI 插件页重载插件（或重启 AstrBot）。
4. 群里发送 `/炒股 开户` 开始玩。

`metadata.yaml` 声明了 `astrbot_version: ">=4.9.2"`（用到 `self.name` 取插件数据目录）。

## 配置

所有参数集中在 [config.py](config.py) 的 `Config` 数据类里，改完重载插件生效：

| 参数 | 默认 | 说明 |
|---|---|---|
| `initial_cash` | `1_000_000` | 初始资金 |
| `lot_size` | `100` | 1 手股数 |
| `limit_main` / `limit_growth` / `limit_bse` / `limit_st` | `0.10` / `0.20` / `0.30` / `0.05` | 各板块涨跌幅 |
| `commission_rate` / `commission_min` | `0.00025` / `5.0` | 佣金费率与最低佣金 |
| `stamp_tax_rate` | `0.0005` | 印花税（仅卖出） |
| `transfer_fee_rate` | `0.00001` | 过户费 |
| `tick_seconds` | `3.0` | 行情推进间隔（秒） |
| `market_mode` | `"247"` | `"247"` 常开演示 / `"realtime"` 真实交易时段 |
| `auction_enabled` | `True` | 是否启用集合竞价阶段（关闭则退化为连续竞价二态） |
| `auction_seconds` / `closing_auction_seconds` | `60` / `45` | 开盘 / 收盘集合竞价时长（秒，虚拟交易日口径） |
| `auction_cancel_ratio` | `0.5` | 竞价前段可撤单的比例（后段不可撤，对应真实 9:20） |
| `vol_scale` / `idio_scale` | `1.15` / `1.0` | 大盘与板块因子 / 个股波动的放大系数 |
| `fat_tail_dof` | `3` | 个股冲击的 t 分布自由度（越小尾越肥） |
| `crash_prob` / `crash_size` | `0.0002` / `(0.010, 0.025)` | 黑天鹅暴跌的频率与幅度 |
| `melt_prob` / `melt_size` | `0.00015` / `(0.008, 0.020)` | 狂欢暴涨的频率与幅度 |
| `jump_decay` | `0.6` | 跳空冲击每 tick 衰减（累积幅度≈幅度/(1−衰减)） |
| `stock_jump_prob` | `0.00003` | 单只股票每 tick 暴雷/暴涨的概率 |
| `stock_jump_neg` / `stock_jump_pos` | `(0.05, 0.10)` / `(0.035, 0.08)` | 暴雷 / 暴涨幅度 |
| `mean_revert` | `0.00005` | 均值回归强度（越小越接近纯随机游走） |
| `sentiment_feedback` | `0.00008` | 情绪指数对大盘的反作用强度 |
| `main_force_enabled` | `True` | 虚拟主力（吸筹/拉升/派发/砸盘）开关 |
| `day_seconds` | `1200` | 247 模式下虚拟交易日长度（秒），到点做日终清算 |
| `mm_spread` / `mm_depth` | `0.002` / `5000` | 做市商价差与每档挂量 |
| `impact_k` | `0.05` | 供需冲击系数（越大越"敏感"） |
| `rebirth_cooldown_hours` | `24` | 重生冷却 |
| `rebirth_cash_factor` | `0.5` | 重生资金相对初始资金的折扣 |
| `rebirth_max_times` | `3` | 终身重生上限 |
| `trade_cooldown_seconds` | `5.0` | 交易指令限流间隔 |
| `log_level` | `"INFO"` | 日志级别：DEBUG / INFO / WARNING / ERROR |
| `log_trades` | `True` | 每笔成交是否写日志 + 落成交流水表 |
| `heartbeat_ticks` | `200` | 每 N 个 tick 打一条心跳日志（0 = 关闭） |
| `market_paused` | `False` | 暂停行情推进（挂单/撤单/日终清算照常） |
| `notice` | `""` | 行情卡片置顶公告，留空不显示（≤200 字） |

> 运维类开关（`market_mode`、`market_paused`、`notice`）都在 WebUI 的「插件设置 → 虚拟股市」里改，改完重载插件生效；聊天里没有管理员指令，需要停用/重载插件请直接在插件页操作。

> `market_mode="realtime"` 时按真实 A 股时段（Asia/Shanghai，9:30–11:30 / 13:00–15:00，周末休市）判断能否下单；`"247"` 模式 7×24 可交易，靠 `day_seconds` 制造"交易日"来让 T+1 与日终清算生效。法定节假日表尚未接入。

## 数据存储

- 数据库：`data/plugin_data/astrbot_plugin_sharemarket/sharemarket.db`（SQLite）
- 表：`accounts`（三本账 + 破产/重生状态）、`positions`（持仓与可卖数）、`orders`（委托与冻结）、`prices`（最新价/昨收/日内高低/成交量）、`trades`（**成交流水，对账用**）、`candles`（**日 K**：code/period/ts/OHLCV；分时只在内存里）、`meta`（日终清算标记）
- 若取不到 AstrBot 官方数据目录，退回插件目录下的 `data/`（重装插件会丢，仅作兜底）

## 日志

日志分两路输出，都不需要额外配置：

1. **AstrBot 日志**：启动时把 AstrBot 自己的 logger 桥接到插件日志上，AstrBot 控制台/日志里能看到带 `[股市]` 前缀的记录。
2. **文件日志**：`data/plugin_data/astrbot_plugin_sharemarket/sharemarket.log`，1 MB 轮转、保留 5 份，UTF-8 编码，用于事后对账排查。

埋点覆盖：插件启动（数据目录 / 模式 / tick / 股票池 / 恢复的行情与挂单 / 账户与冻结统计）、行情心跳（tick 数、均涨跌幅、账户与成交累计）、`tick` 异常（**带完整堆栈且不影响循环继续**）、每笔成交（主动/被动、成交价、费用、委托号）、下单与撤单（冻结与释放金额）、拒单与限流（WARNING）、开户、L3 破产判定、重生、日终清算开始/完成（过期委托数、释放冻结、T+1 解锁）。

业务模块统一用标准库 `logging`（`log.get_logger("trade")` 这样的命名空间），只有 `main.py` 负责把 AstrBot logger 与文件 handler 挂上去——这样业务逻辑可以脱离 AstrBot 离线测试，日志也能被测试捕获断言。

## 已知限制 / 路线图

**当前状态**：插件已在真实 AstrBot（4.28.x，本机 `data/plugins/` 下）加载并跑过完整虚拟交易日，`sharemarket.log` 里有 tick、成交、日终清算的实际记录；早期「从未加载」的说法已过时。仍有两块没有实测证据：QQ 官方机器人平台上的图片消息发送（`event.image_result` 在真实适配器上的表现）与多群并发压力。

**已知限制**

- 图片卡片依赖 Pillow；缺 Pillow 或发送失败时自动降级为文本，功能不缺但视觉信息少。
- 分时 K 线只保留当日内存样本（`bars_per_day` 根），重启会丢当日分时；日 K 落库不受影响。
- 法定节假日表只覆盖 2024–2026，之后需要补表。

**路线图（原 P1/P2 已全部落地）**

集合竞价（开盘 + 收盘）、板块联动 / 情绪指数 / 虚拟主力、K 线与技术指标、新闻事件 / 分红送股 / 停牌复牌 / 打新、融资融券（含 130% 维保与强平）、ST 戴帽摘帽、退市清算、成就与赛季、道具商店、日常任务、NPC 常开、龙虎榜 / 资金流 / 异动榜。

**可能的下一步**：QQ 官方适配器上的图片消息实测、多群并发压测、节假日表年度维护、分时数据的跨重启持久化。
